## 要件: BezierWpf (.NET 10 版) と同じ機能・同じ構造
計画を書く前に BezierWpf のソースと README を読み、次の点を WPF 版と揃える。
- 機能: メニュー (またはツールバー) で「線分」「矩形」「曲線」を切り替え、ドラッグで図形を追加する。起動直後は何も描かない Edit モード。
- 入力: マウスは左ボタンだけを対象とする。押下位置からの距離が 10 CSS px 以上になったらドラッグとし、それ未満で解放したらクリックとする。判定前の移動位置を蓄積し、ドラッグと判定した時点で、押下位置での DragStart と蓄積した位置の Dragging を順番に通知する。クリックだけでは図形を追加しない。
- 入力の終了: 描画領域の外でボタンを解放してもドラッグを終了できるようにする。キャプチャーを失った場合は最後に把握した位置で終了し、待機状態に戻す。通常の解放に続くキャプチャー喪失で終了処理を二重に行わない。
- 曲線: ドラッグの開始位置を最初の通過点とし、最後に採用した通過点からの距離が 16 CSS px を超えたときだけ点を追加する (16 ちょうどでは追加しない)。3 点以上たまったら描く。
- 曲線の確定: `ReshapeLast` と同じく、通過点が 2 点以上あり、終点と最後の通過点の距離が 16 CSS px 以下なら最後の点を終点で置換する。それ以外では終点が最後の点と異なる場合だけ追加する。最終的に 3 点以上なら終点を通る曲線を描き、2 点以下なら表示しない。
- アルゴリズム: 自然3次スプライン (`ToSplineTangents` / `ToSplineBezier`。トーマス法) で区間ごとの3次ベジエに変換する。閉じた曲線 (`ToClosedSplineBezier`) と比較用の Catmull-Rom 版も、他の版と同様に移植するかどうかを未決事項に挙げる。
- 構造: `MouseEventConverter` (クリック/ドラッグへの変換) → `Controller` → `Command` (Edit / Line / Rectangle / Bezier、AddCommand の Template Method) という MVC + Command パターンを、JavaScript のクラスで対応させる。WPF 版のクラス・メソッドとの対応表を計画書に載せる。
- 規約: 変換コードなどのプロジェクト間の重複は教材として意図的なもの。2 つの HTML 版の間でも共通化しない。

## 座標系と高 DPI
- 入力座標・距離のしきい値・線幅は、描画領域内の CSS ピクセル単位で統一する。WPF 版の線幅 3 に対応させ、線幅は 3 CSS px とする。
- Canvas の内部画素数と論理座標を分離し、`devicePixelRatio` が変わってもドラッグ開始距離・間引き間隔・図形の表示サイズを変えない。SVG も同じ論理座標で扱い、イベント座標からの変換方法を計画書に示す。
- 高 DPI 対応の具体的な実装方法と、描画領域のリサイズ時のサイズ・座標・再描画の扱いを検討する。Canvas のサイズ変更で内容が消える場合も、保持している図形を再描画できる設計にする。

## 曲線の計算は独立した JavaScript ファイルにする
- WPF 版で `Geometry.cs` (`Geo` / `GeometryExtensions`) が描画から切り離されているのと同じように、座標の配列から3次スプラインを求める関数群は、それぞれの版で独立した JavaScript ファイルにする (例: `BezierCanvas/geometry.js`、`BezierSvg/geometry.js`)。
- 入力は座標 (`{x, y}`) の配列、出力はベジエ曲線の集まりを表す点列 `[P0, 制御点1, 制御点2, P1, 制御点1, 制御点2, P2, …]` (入力点数 n が 2 以上なら 1 + 3(n − 1) 点) とし、WPF 版の `ToSplineBezier` と同じ形にする。0 点・1 点の戻り値も WPF 版の実装を確認して明記する。計算関数は 2 点から利用できるが、操作時の曲線描画は上記の 3 点以上という条件に従う。
- 計算関数は DOM・Canvas・SVG に依存しない純粋な関数にする (ブラウザと Node 向けの公開処理は許容する)。Canvas 版はこの点列を `bezierCurveTo` に、SVG 版は `<path>` の `d` 属性 (`M … C …`) に変換して使う。この変換は描画側のファイルに置く。
- ブラウザでは classic script (`<script>` で読み込む) とし、同じファイルを Node のテストからも読み込めるようにする。グローバル名前空間と CommonJS の条件付き公開など、両立のための公開方式を未決事項に挙げる。ES Modules やローカルサーバー必須の方式は採用しない。
- 2 つの版の geometry.js は同じ内容になるが、上記の規約どおり共通化せず、それぞれのフォルダーに置く。

## 2 つの版
### 1. BezierCanvas (HTML + Canvas + JavaScript)
- 描画は Canvas 2D (`bezierCurveTo`)。確定済みの図形をモデルに保持し、変更のたびに全体を再描画する (WinForms 版の `OnPaint` に近い即時モード)。
- ドラッグ途中の図形も毎回の再描画対象に含め、確定済みの図形と一緒に表示する。モデルに追加するタイミングと作図中の参照の管理を示し、確定時に図形が二重登録されない設計にする。

### 2. BezierSvg (HTML + SVG + JavaScript)
- 描画は SVG 要素 (`<line>` / `<rect>` / `<path d="M … C …">`) を DOM に追加し、属性を書き換えて形を変える (WPF 版の `Shape` を `Canvas` に追加する保持モードに近い)。

計画書では、この「即時モード (Canvas) と保持モード (SVG)」の違いを教材としての見どころとして説明する。

## 制約
- ビルドツール・npm パッケージ・フレームワークは使わない。素の HTML / CSS / JavaScript (ES2020 程度) のみ。
- ブラウザで `index.html` を `file://` から直接開くだけで動くことを必須とする。ローカルサーバーの起動や npm パッケージのインストールを実行条件にしない。
- Pointer Events と Mouse Events のどちらを使うかは未決事項に挙げ、上記の入力動作をどのように満たすかを示す。Pointer Events を採用する場合は、対象にするポインター・同時入力の扱いと、`pointercancel`・`lostpointercapture` 時の終了処理も明記する。
- .sln には含めない (含める方法があるなら選択肢として挙げる)。
