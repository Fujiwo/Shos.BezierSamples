## 1. 目的

Win32 (C++)・WinForms・WPF に続いて、同じ「すべての通過点を通る曲線を描く」サンプルを、ブラウザで動く HTML/JavaScript で 2 つ書き分ける。

| 版 | 描画の方式 | WPF 系で近いもの |
|---|---|---|
| `BezierCanvas` | **即時モード**。確定済みの図形をモデルに持ち、変わるたびに全体を `bezierCurveTo` などで描き直す | WinForms 版の `OnPaint` |
| `BezierSvg` | **保持モード**。`<line>` / `<rect>` / `<path>` を DOM に追加し、属性を書き換えるとブラウザが描き直す | WPF 版の `Shape` を `Canvas` に追加する方式 |

機能と構造は BezierWpf (.NET 10 版) にそろえる。同じ入力処理 (`MouseEventConverter`)、同じ MVC + Command パターン、同じ曲線のアルゴリズム (自然 3 次スプライン) を、描画の方式だけが違う 2 つの版で見比べられるようにする。これが教材としての見どころになる (4.9)。

### 2.2 移植で守る動作 (ソースで確かめた値)

| 項目 | BezierWpf の実装 |
|---|---|
| ドラッグ開始 | 押下位置からの距離が `dragStartLength = 10` **以上** (`>=`) でドラッグ。判定前の移動位置は `Queue` にため、判定時に `DragStart(押下位置)` → ためた位置の `Dragging` (判定のきっかけの位置も含む) の順に通知する |
| クリック | 押下中のまま解放すると `Click(解放位置)`。ためた位置は捨てる。`EditCommand` / `AddCommand` はクリックで何もしない |
| 解放とキャプチャー | 押下時に `CaptureMouse()`。解放で `DragEnd(解放位置)` → 待機中に戻してから `ReleaseMouseCapture()`。続く `LostMouseCapture` は待機中なので何もしない |
| キャプチャー喪失 | ドラッグ中なら `DragEnd(最後に把握した位置)`。押下中ならクリックにせず捨てる。どちらも待機中に戻す |
| 図形の追加 | `AddCommand.OnDragging` の最初の呼び出しで図形を作り、Model に追加する。`OnDragEnd` で `ReshapeLast` してから参照 (`Shape`) を手放す |
| 線の属性 | 黒、太さ 3。塗りつぶしなし |
| 矩形 | 2 点から正規化した `Rect` で、左上と幅・高さを設定する (どの方向へのドラッグでも正しく描く) |
| 曲線の点 | 開始位置を最初の通過点にし、最後の通過点からの距離が `sensitivity = 16` **を超えた** (`>`) ときだけ追加する。3 点以上で描く |
| 曲線の確定 (`ReshapeLast`) | 2 点以上あり、終点と最後の点の距離が 16 **以下**なら最後の点を終点で置換する。それ以外は終点が最後の点と異なるときだけ追加する。3 点以上なら描く。2 点以下なら `Path.Data` は設定されず、空の `Path` が残る (表示されない) |

### 2.3 曲線の変換関数の戻り値 (BezierWpf の `GeometryExtensions`)

| 関数 | 0 点 | 1 点 | 2 点 | n 点 (下限以上) |
|---|---|---|---|---|
| `ToSplineTangents` | 空 | `[(0, 0)]` (対角 2、右辺 0 を解いた結果) | 2 個 | n 個 |
| `ToSplineBezier` | 空 (入力をそのまま返す) | `[P0]` (入力をそのまま返す) | 4 点 (直線状のベジエ) | 1 + 3(n − 1) 点 |
| `ToClosedSplineTangents` | 空 | `[(0, 0)]` | 開いた曲線の接線 | n 個 (3 点以上) |
| `ToClosedSplineBezier` | 空 | `[P0]` | `[P0, P1]` (入力をそのまま返す) | 1 + 3n 点 (3 点以上) |
| `ToBezierPolyline` (Catmull-Rom) | 入力をそのまま返す (4 点未満) | 〃 | 〃 | 1 + 3(n − 3) 点 (4 点以上) |
| `ToBezierPolygon` (Catmull-Rom) | 入力をそのまま返す (3 点未満) | 〃 | 〃 | 1 + 3n 点 (3 点以上) |

ほかの版の状況: 閉じた曲線 (`ToClosedSplineBezier`) は WinForms・WPF・WpfCad2Lib にあり、Win32 には無い。Catmull-Rom 版はすべての版に残っている。

## 3. 方針

- 素の HTML / CSS / JavaScript (ES2020 程度) だけで書く。ビルドツール・npm パッケージ・フレームワークは使わない。
- `index.html` を `file://` で直接開くだけで動かす。そのため、スクリプトは classic script (`<script src>`) にする。ES Modules は `file://` では読み込めない (CORS で拒否される) ので使わない。
- BezierWpf のクラス・メソッドと 1 対 1 で対応させる (4.3 の対応表)。名前は JavaScript の慣習 (クラスは PascalCase、メソッド・プロパティは camelCase) にする。
- 座標・距離のしきい値・線幅は、描画領域の左上を原点とする CSS ピクセルで統一する。`devicePixelRatio` の影響は Canvas の内部画素数だけに閉じ込める (4.7)。
- 曲線の計算は DOM に依存しない `geometry.js` にまとめ、描画への変換 (`bezierCurveTo` / `d` 属性) は描画側に置く (4.6)。
- 2 つの版のあいだでも、`geometry.js` を含めてコードを共通化しない。各フォルダーだけで読めるようにする (CLAUDE.md の規約と同じ)。
- 自動テストは Node 標準の `node:test` / `node:assert` で書き、npm パッケージを使わない。Node はテストのためだけに使い、ブラウザでの実行には要らない。
- ES2020 に収めるため、クラスフィールド (`x = 0;`、`#private`)・`Array.prototype.at`・`Object.hasOwn` など ES2022 以降の機能は使わない。初期化はコンストラクターで行う。

### 4.2 スクリプトの公開方式 (ブラウザと Node の両立)

classic script では、別ファイルのトップレベルの `class` / `const` 宣言も同じグローバルなスコープに入るので、後に読み込むファイルから参照できる。Node (CommonJS) ではファイルごとにスコープが分かれるので、テストから読み込むには `module.exports` で公開する必要がある。方式は 7 章の 2 で決める。推奨案 (A) は次の形。

```js
// geometry.js (推奨案 A の例。計画用のスケッチで、まだ動かしていない)
"use strict";

const Geometry = (() => {
    // 内部の関数 (solveTridiagonal など) は外から見えない
    function solveTridiagonal(lower, diagonal, upper, right) { /* … */ }
    function toSplineTangents(points) { /* … */ }
    function toSplineBezier(points) { /* … */ }

    return { toSplineTangents, toSplineBezier /* , … */ };
})();

// Node (テスト) から require されたときだけ公開する。ブラウザでは module が無いので何もしない
if (typeof module === "object" && module.exports)
    module.exports = Geometry;
```

- ほかのファイルも同じく、トップレベルに `class Controller { … }` などを宣言し、末尾で条件付きで `module.exports = { Controller };` とする。
- ファイル間の参照 (`command.js` から `Geometry` など) は、読み込み時ではなく**呼び出し時**に解決する自由な名前として書く。テストでは依存するファイルを先に `require` して `globalThis` に置いてから、対象を `require` する。
- 同じ名前のトップレベル宣言が 2 つのファイルにあると、ブラウザでは 2 つめの読み込みが `SyntaxError` になる。依存先を `const Geometry = require(…)` のように受け取り直すことはしない。

### 4.4 入力: `MouseEventConverter`

#### 状態遷移の本体 (DOM に依存しない)

BezierWpf の `Point` を受け取るオーバーロードを、そのまま移す。

```text
待機中     (isStarted = false, isDragging = false)
  │ onButtonDown(p): startPosition = lastPosition = p
  ▼
押下中     (isStarted = true , isDragging = false) … onMove(p) の位置を draggingPositions にためる
  │ |p − startPosition| >= 10 → dragStart(startPosition)、ためた位置を順に dragging(…)
  ▼
ドラッグ中 (isStarted = true , isDragging = true ) … onMove(p) ごとに dragging(p)
  │ onButtonUp(p) → dragEnd(p)
  ▼
待機中
押下中に onButtonUp(p) → click(p)、ためた位置を捨てる
onLostCapture() → ドラッグ中なら dragEnd(lastPosition)。どの状態からも待機中に戻し、ためた位置を捨てる
```

- 距離は `Math.hypot(dx, dy)` で求める。
- 終了処理の一回性: `onButtonUp` で先に待機中に戻すので、続く `onLostCapture` では何も起きない (WPF 版と同じ)。

#### Pointer Events との接続 (7 章の 3 で Pointer Events を選んだ場合)

| イベント | 処理 |
|---|---|
| `pointerdown` | 対象のポインター (下記) で `event.button === 0` のとき、`activePointerId = event.pointerId` を記録して `onButtonDown(位置)`、`element.setPointerCapture(event.pointerId)` |
| `pointermove` | 待機中に、対象のポインターから `event.button === 0` かつ `event.buttons & 1` のイベントが届いたら、`pointerdown` と同じく押下として扱う (コード化されたボタン操作、下記)。操作中は `event.pointerId !== activePointerId` なら無視し、`event.button === 0` で `(event.buttons & 1) === 0` なら解放として扱う (`pointerup` と同じ処理)。それ以外は `onMove(位置)`。待機中のそれ以外の移動 (ボタンを押していない移動) は無視する |
| `pointerup` | 対象のポインターで `event.button === 0` のとき、`onButtonUp(位置)` → `activePointerId = null` → `releasePointerCapture` |
| `pointercancel` | 対象のポインターなら `onLostCapture()` (最後に把握した位置で終える。`pointercancel` の座標は使わない) → `activePointerId = null` |
| `lostpointercapture` | 対象のポインターなら `onLostCapture()` → `activePointerId = null`。通常の解放の後は待機中なので何も起きない |

- **左ボタンだけを対象にする:** Pointer Events では、ほかのボタンを押したまま左ボタンを押す・離すと、`pointerdown` / `pointerup` ではなく `pointermove` (`button` が 0) として届く (コード化されたボタン操作)。そのため、左ボタンの変化は 3 つのイベントのどれでも「`event.button === 0` と `event.buttons & 1`」で判定する。右ボタン・中ボタンだけの操作 (`button` が 1 や 2) は無視する。
- **対象のポインターと同時入力:** 7 章の 4 で決める。推奨案では、`isPrimary` のポインター (マウス・ペン・最初に触れた指) を対象にし、操作中 (`activePointerId !== null`) はほかのポインターの `pointerdown` を無視する。タッチで画面がスクロールしないよう、描画領域に `touch-action: none` を指定する。
- **領域の外での解放:** `setPointerCapture` により、ポインターが描画領域やブラウザの外に出ても、`pointerup` は描画領域の要素に届く。
- **キャプチャーを失った場合:** `lostpointercapture` と `pointercancel` のどちらでも、最後に把握した位置で `dragEnd` してから待機中に戻す。`pointercancel` の後には `lostpointercapture` も届くが、待機中なので二重に終了しない。
- **解放を取りこぼした場合:** ウィンドウの外で解放されて `pointerup` が届かなかった場合も、次に届いた `pointermove` の `buttons` に左ボタンが無ければ、その位置で解放として扱う (WPF の `e.LeftButton == MouseButtonState.Pressed` の確認に相当)。
- `setPointerCapture` は、ポインターがすでに無効なときに例外を投げることがある。その場合は待機中に戻す。
- テキストの選択やドラッグ & ドロップの開始を防ぐため、描画領域に `user-select: none` を指定し、`pointerdown` で `preventDefault()` する。

#### 座標の変換

```js
// 描画領域 (枠線・余白なし) の左上を原点とする CSS ピクセルの座標
toPosition(event) {
    const rect = this.element.getBoundingClientRect();
    return { x: event.clientX - rect.left, y: event.clientY - rect.top };
}
```

- Canvas 版・SVG 版とも同じ式を使う。`offsetX` / `offsetY` は使わない。SVG では `event.target` が子要素 (`<path>` など) になり、どの要素が基準になるかが分かりにくいため。
- 描画領域の要素には `border` / `padding` / CSS の `transform` を付けない。付けると、この式と描画の座標がずれる。
- SVG 版は `viewBox` を指定しない。このとき SVG のユーザー単位は CSS ピクセルと一致するので、上の座標をそのまま `x1` などの属性に使える。拡大縮小などを入れる場合は `svg.getScreenCTM().inverse()` で変換する方法があることを、コメントで触れる。
- `getBoundingClientRect()` はイベントのたびに呼ぶ。スクロールやリサイズで要素の位置が変わっても、ずれないようにするため。

### 4.5 コマンドとモデル

#### 共通 (両版)

- `Command` は何もしない `onClick` / `onDragStart` / `onDragging` / `onDragEnd` と、`model` のプロパティを持つ。`EditCommand` は `Command` をそのまま継承する。
- `AddCommand` の流れは WPF 版と同じにする。
  - `onDragStart(p)`: `startPosition = p`、`figure` (SVG 版は `shape`) を `null` にして `onStart()`
  - `onDragging(p)`: 最初の呼び出しで `createFigure()` → 属性の設定 → `model.add(…)`。続けて `reshape(p)`
  - `onDragEnd(p)`: `reshapeLast(p)` → 参照を `null` にする
- 点の等しさは、`x` と `y` の値で比べる (`p.x === q.x && p.y === q.y`)。オブジェクトどうしの `!==` は参照の比較なので、WPF 版の `position != lastPosition` をそのまま移すと、いつも「異なる」になってしまう。
- `BezierCommand` の点の採用は WPF 版と同じ (2.2)。間引きは `distance > 16`、確定時の置換は `count >= 2 && distance <= 16`、追加は「等しくない」とき。

#### BezierCanvas: 即時モードでの作図中の図形

- 図形は `LineFigure` / `RectangleFigure` / `BezierFigure` で、それぞれ自分を描く `draw(context)` を持つ。
- 作図中の図形も、**最初の `onDragging` で 1 度だけ `model.add` する** (WPF 版の `Model?.Add(Shape)` と同じタイミング)。
  - `reshape` / `reshapeLast` (派生クラス) は図形のデータを書き換えるだけにする。`AddCommand` の `onDragging` / `onDragEnd` が、その後に `model.update()` を呼んで View に再描画を求める。派生クラスは通知を気にしなくてよい。
  - `onDragEnd` は `reshapeLast` → `model.update()` の後、参照 (`figure`) を手放すだけで、追加はしない。
  - 追加は `onDragging` の 1 か所だけなので、確定時に二重登録にならない。
  - ドラッグ途中の図形はモデルの中にあるので、確定済みの図形と一緒に、毎回の再描画で描かれる。
- 別案 (作図中の図形をモデルの外に持ち、確定時に追加する WinForms 版の方式) は、7 章の 5 に挙げる。
- `Model.update()` は登録された View に通知し、View は `requestAnimationFrame` で 1 フレームに 1 回だけ全体を描き直す (WinForms の `Invalidate` → `OnPaint` に相当)。
- `BezierFigure.draw` は、点が 3 個以上のときだけ描く。2 個以下で確定した曲線はモデルに残るが、何も描かない (WPF 版で空の `Path` が残るのと同じ。7 章の 6)。

#### BezierSvg: 保持モード

- `createShape()` は `document.createElementNS("http://www.w3.org/2000/svg", "line")` などで要素を作り、`model.add` (`appendChild`) で表示する。以降は `setAttribute` で形を変えるだけで、ブラウザが描き直す。
- 属性は `stroke="black"`、`stroke-width="3"`、`fill="none"` にする。SVG は塗りつぶしの既定が黒なので、`fill="none"` が必須になる (WPF の `Shape.Fill` の既定は無し)。
- `<rect>` は `width` / `height` に負の値を指定できないので、WPF 版と同じく 2 点から正規化する。
- 曲線は、3 点以上のときだけ `d` を設定する。2 点以下で確定すると `d` の無い `<path>` が残り、何も表示されない (WPF 版と同じ)。
- `stroke-miterlimit` は 10 にする。WPF と Canvas の既定は 10、SVG の既定は 4 で、鋭い角の見え方をそろえるため。

#### 線の見え方の違い (README に書く)

WPF の `Rectangle` は、線を図形の内側に描く (幅・高さの中に線が収まる)。Canvas の `strokeRect` と SVG の `<rect>` は、線を輪郭の中心に描くので、外側に 1.5 CSS px はみ出す。HTML 版は標準の描き方のままにして、この違いを README に書く。

### 4.6 曲線の計算: `geometry.js`

- 入力は `{x, y}` の配列。出力は新しい配列で、要素も新しい `{x, y}` オブジェクトにする (入力を変更せず、入力の要素とも共有しない)。
- 公開する関数と戻り値 (WPF 版に合わせる。2.3)。

| 関数 | 戻り値 |
|---|---|
| `toSplineTangents(points)` | n 個の接線。0 点なら `[]`、1 点なら `[{x: 0, y: 0}]` |
| `toSplineBezier(points)` | 2 点以上なら 1 + 3(n − 1) 点 `[P0, 制御点1, 制御点2, P1, …]`。0 点なら `[]`、1 点なら `[P0]` (入力の写し) |
| `toClosedSplineTangents(points)` (7 章の 1) | 3 点以上なら周期スプラインの接線、3 点未満なら `toSplineTangents` の結果 |
| `toClosedSplineBezier(points)` (7 章の 1) | 3 点以上なら 1 + 3n 点で P0 に戻る。3 点未満なら入力の写し |
| `toBezierPolyline` / `toBezierPolygon` / `toBezier` (7 章の 1) | WPF 版と同じ (Catmull-Rom、比較用) |

- 計算の手順は WPF 版の `SolveSplineTangents` / `SolveClosedSplineTangents` (Sherman-Morrison、γ = −4) / `SolveTridiagonal` / `ToHermiteBezier` を、そのまま移す。
- x 座標と y 座標は、同じ係数行列で右辺だけを替えて 2 回解く (WPF 版と同じ)。
- 計算関数は 2 点から使える。画面で曲線を描くのは、`BezierCommand` の条件どおり 3 点以上のときだけにする。
- `geometry.js` は DOM・Canvas・SVG を参照しない。公開処理 (4.2) だけが、ブラウザと Node の違いを扱う。

#### 描画側への変換

```js
// BezierCanvas/graphic-helper.js: bezierPoints は [P0, C1, C2, P1, C1, C2, P2, …]
context.moveTo(bezierPoints[0].x, bezierPoints[0].y);
for (let index = 1; index + 2 < bezierPoints.length; index += 3)
    context.bezierCurveTo(bezierPoints[index].x, bezierPoints[index].y,
                          bezierPoints[index + 1].x, bezierPoints[index + 1].y,
                          bezierPoints[index + 2].x, bezierPoints[index + 2].y);

// BezierSvg/graphic-helper.js: "M x0 y0 C x1 y1 x2 y2 x3 y3 C …" (2 区間目以降も C を付けて読みやすくする)
```

- `d` の数値は丸めずに `String(number)` で書く。テストで値を確かめやすく、誤差も入らない。

### 4.7 高 DPI とリサイズ

#### BezierCanvas

- `<canvas>` の表示サイズは CSS で決める (`display: block; width: 100%; height: 100%`)。内部の画素数 (`canvas.width` / `canvas.height`) は、表示サイズ × `devicePixelRatio` を丸めた値にする。
- 描くたびに、`context.setTransform(canvas.width / cssWidth, 0, 0, canvas.height / cssHeight, 0, 0)` で CSS ピクセルの座標を内部の画素に合わせる。丸めた画素数から倍率を求めるので、表示サイズと内部の画素がずれない。
- そのため、図形の座標・線幅 3・しきい値 (10 / 16) は、`devicePixelRatio` に関係なくすべて CSS ピクセルで扱える。
- 表示サイズの変化は、`<canvas>` を `ResizeObserver` で監視して知る。CSS でサイズを決めているので、内部の画素数を変えても表示サイズは変わらず、監視が繰り返し発生しない。
- `devicePixelRatio` だけが変わる場合 (表示倍率の違うモニターへの移動など) は、表示サイズが変わらないことがある。`matchMedia("(resolution: <現在の値>dppx)")` の `change` で検知し、そのたびに新しい値で登録し直す。
- `canvas.width` を設定すると、Canvas の内容は消える。しかし図形はすべてモデルにあるので、サイズの変更の直後に全体を描き直せば元に戻る。`ResizeObserver` のコールバックは描画の前に呼ばれるので、その中で描き直してちらつきを防ぐ。
- 描画領域の大きさが変わっても、図形の座標は変えない (左上を原点とする CSS ピクセルのまま)。小さくした場合、はみ出した部分は見えなくなるが、元の大きさに戻すと再び表示される (WPF の `Canvas` と同じ)。
- 再描画の流れ: `invalidate()` (`requestAnimationFrame` の予約。予約済みなら何もしない) → `render()` (`setTransform` → `clearRect` → 各図形の `draw`)。`render` はコンテキストと図形の配列とサイズを受け取る関数にして、テストで偽のコンテキストを渡せるようにする。

#### BezierSvg

- `<svg>` も CSS で表示サイズを決め、`viewBox` を付けない。SVG はベクターなので、`devicePixelRatio` が変わっても、ブラウザが図形を高解像度で描き直す。特別な処理は要らない。
- 表示サイズが変わっても、図形の座標は変わらない。はみ出した部分は `overflow: hidden` で隠す。
- この「Canvas 版は高 DPI とリサイズの処理が必要で、SVG 版は要らない」点も、即時モードと保持モードの違いとして README で説明する。

#### ブラウザの拡大 (Ctrl + / −)

拡大すると `devicePixelRatio` と描画領域の CSS サイズが変わる。図形は CSS ピクセルで持っているので、拡大率に応じて表示上も大きくなる (線幅・しきい値も、CSS ピクセルとして同じ)。Canvas 版は、内部の画素数を増やして描き直すので、ぼやけない。

### 4.8 画面

- 上にツールバー (「線分」「矩形」「曲線」のボタン)、残りすべてを描画領域にする (`html, body { height: 100%; margin: 0 }`、縦の flex)。描画領域の背景は WPF 版と同じ `#FFC080`。
- 起動直後は `EditCommand`。どのボタンも選ばれていない状態で、ドラッグしても何も描かない。
- 選んでいるボタンを `aria-pressed="true"` と見た目で示す。WPF 版のメニューには表示が無いが、ブラウザでは状態が分からないと操作しにくいため (7 章の 7)。
- 確認のため、`main.js` のトップレベルの `const` (`model` / `controller` など) は、DevTools のコンソールから参照できる。

### 4.9 教材としての見どころ: 即時モード (Canvas) と保持モード (SVG)

同じ `MouseEventConverter` → `Controller` → `Command` の流れから、描画の方式だけが違う 2 つの版ができる。README では、次の表と説明図 (5 章の段階 4) で比べる。

| | BezierCanvas (即時モード) | BezierSvg (保持モード) |
|---|---|---|
| 図形を持つもの | アプリのモデル (`Model.figures`。普通のオブジェクトの配列) | DOM (`<svg>` の子要素)。DOM がそのままモデルになる (WPF の `UIElementCollection` と同じ) |
| 図形を描く処理 | 図形ごとの `draw(context)` をアプリが書く | ブラウザが描く。アプリは要素と属性を作るだけ |
| 形を変えたとき | データを書き換え、`model.update()` → `invalidate()` → 全体を消して描き直す | 属性を書き換えるだけ。描き直しはブラウザが行う |
| 作図中の図形 | モデルの中にあり、毎回の再描画で確定済みの図形と一緒に描く | DOM に追加済みの要素の属性を書き換える |
| 高 DPI | 内部の画素数を `devicePixelRatio` に合わせ、`setTransform` で CSS ピクセルに合わせる | ベクターなので不要 |
| リサイズ | 内部の画素数を変えると内容が消えるので、モデルから描き直す | 何もしなくてよい |
| 曲線の形式 | `moveTo` + `bezierCurveTo` の呼び出し | `d` 属性の文字列 `M … C …` |
| 向いている用途 | 図形が非常に多い・毎フレーム全体が変わる描画 | 図形ごとの選択・イベント・スタイルの変更 (DevTools で要素を確かめられる) |
| 近い版 | WinForms 版 (`OnPaint`) | WPF 版 (`Shape` を `Canvas` に追加) |

| ドラッグ開始 (一致) | down (0, 0) → move (6, 8) | 距離 10 なので `dragStart(0, 0)`、`dragging(6, 8)` |
| ドラッグ開始 (超過) | down (0, 0) → move (3, 0) → move (6, 0) → move (11, 0) | `dragStart(0, 0)`、`dragging(3, 0)`、`dragging(6, 0)`、`dragging(11, 0)` の順 |
| 判定後の移動 | 上に続けて move (20, 0) → up (25, 0) | `dragging(20, 0)`、`dragEnd(25, 0)` |
| キャプチャー喪失 (ドラッグ中) | ドラッグ中に move (30, 5) → lostCapture | `dragEnd(30, 5)`。その後の move では何も通知しない |
| キャプチャー喪失 (押下中) | down → move (3, 0) → lostCapture → down (50, 50) → up (50, 50) | 喪失では何も通知しない。次は `click(50, 50)` だけ (ためた位置が残らない) |
| 終了処理の一回性 | ドラッグ → up → lostCapture | `dragEnd` は 1 回だけ |
| 解放の取りこぼし | ドラッグ中に `buttons` が 0 の `pointermove` | その位置で `dragEnd` (偽のイベントを使う) |
| Pointer Events の振り分け | 偽の要素とイベント (`button` / `buttons` / `pointerId` / `isPrimary` / `clientX`)。右ボタン、2 本目のポインター、コード化されたボタン操作、`pointercancel` → `lostpointercapture` | 左ボタン・対象のポインターだけを通知する。`setPointerCapture` / `releasePointerCapture` が呼ばれる。`pointercancel` の後の `lostpointercapture` で二重に終了しない |
| 座標の変換 | 偽の `getBoundingClientRect` (left 100, top 40) と `clientX/Y` | 描画領域の左上を原点とする座標 |
| 曲線の間引き | 開始 (0, 0) から距離 15 / 16 / 16.001 の移動 | 15・16 では追加せず、16.001 で追加 (最後に採用した点から測る) |
| 曲線の確定 (置換) | 2 点以上あり、終点が最後の点から距離 16 | 最後の点を終点で置換 (点数は変わらない) |
| 曲線の確定 (追加) | 終点が最後の点から距離 16.001 / 1 点だけで距離 5 | 追加する |
| 曲線の確定 (同じ点) | 終点が最後の点と同じ座標 (別のオブジェクト) | 追加しない |
| 3 点未満の非表示 | 確定時に 2 点 | Canvas 版は `draw` で何も描かない。SVG 版は `d` を設定しない |
| Edit モード | `EditCommand` にクリック・ドラッグ | モデルが変わらない |
| Controller | `command` → `model` の順、`model` → `command` の順で設定 | どちらでも Command に Model が渡る |

- SVG 版のコマンドは `document.createElementNS` を使うので、テストでは `globalThis.document` に偽の document (`setAttribute` / `getAttribute` を記録する要素を返す) を置く。Model には `add` を記録する偽のオブジェクトを渡す。
- Canvas 版のコマンドと図形は DOM を使わないので、そのまま検証できる。
